# Cluster launchers

Scripts for the CSI Slurm cluster through Open OnDemand (Job Composer). Each `ood-*.txt` is the Job Composer paste of the matching `job-*.sbatch`. A launcher pulls the Apptainer bundle image, mounts one reviewed patch ZIP from `reports/` read-only over `src/`, `tools/` and two vendor files, verifies the ZIP SHA-256 and the checksums of the mounted tree inside the container, and only then starts `tools/parallel_eval.py` (or a provenance continuation that wraps it).

## Current (v6 experiment `phys-pro6000-100-v6`)

| Launcher | Purpose |
|---|---|
| `ood-fastwam-pro6000x2-v6-context.txt` / `job-pro6000x2-fastwam-v6-context.sbatch` | Finish any unfinished pool task with 8 parallel seed workers, run the success-context continuation, then evaluate the models in `ROBOTWIN_MODELS` one after another. Two PRO 6000, 4 pool workers per GPU, 4 policy replicas spread over both GPUs; stages and binds OIDN 2.3.3 for Blackwell and runs a render probe (`OIDN_PASS`); v6 hard-links the G0.5 runtime bundle (`G05_RUNTIME_FIX`). Generated by `tools/package_success_context_fix.py`. |
| `ood-fastwam-pro6000x2-v6-all.txt` / `job-pro6000x2-fastwam-v6-all.sbatch` | Fresh v6 pool followed by Fast-WAM evaluation (superseded by the context launcher for continuing runs). |
| `ood-pool-pro6000-v6-fresh.txt` / `job-pro6000-pool-fresh-v6.sbatch` | Pool preparation only. |
| `run_parallel.sh`, `run_bundle.sh` | In-container entry points used by the launchers. |
| `monitor_pool.py`, `ood-pool-monitor-v5.txt` | Read-only progress monitor for a running pool. |
| `default-protected.txt` | The site's protected default-script section that every launcher must keep verbatim. |

## Historical (v5 experiment and incident fixes)

The `*-v5-*`, `*-diagnose-*`, `*-expert-fix`, `*-geometry-*`, `*-curobo-*`, `*-provenance-*`, `*-refill-*` launchers belong to the superseded v5 pool and its sequence of reviewed fixes. They are retained because the tests pin them against their delivered patch ZIPs and the incident notes in `docs/` cite them. Scripts that nothing references any more live in `legacy/`.

To resubmit after the 3-day limit, submit the same launcher again: completed episodes and sealed pools are reused, and a job refuses to run if the mounted tree differs from the pinned snapshot.
